# Design

## Context

Стенд ходит к METF через `metf.py` (обёртка над `metf_python_client`): повторы по радио, аптайм в
заголовке, подтверждение чтения лога. Код над ним — `dut.py` (воздействия по номерам выводов
METF), `logwatch.py` (лог и счётчики потерь `serial_stat`), `clock.py` (HTTP `/ntp` METF),
`stand.py`/`conftest.py` (подъём, уборка, сводка перезагрузок METF).

Программатор 0.7.0 (`waterius_flasher`, спека `bench-control`): одна строка команды — одна строка
ответа; `#wave` отвечает сразу длиной пачки и не блокирует порт; `#wave stat` — JSON о последней
начатой пачке с `edges_ms` по часам программатора; `#hold`/`#release` идемпотентны, на линии с
идущей пачкой — `линия занята`; `#log` — заголовок `# log: <n> <потери>` и n байт, не больше 4096
за ответ, кольцо 64 КБ; `#esp log` линий не трогает, а `#lines off` закрывает приём лога.
Уровень `1` в пачке — линия отпущена, а не выведена в 1.

Роутер `2.5.0-waterius.1`: консоль — SSH на 2323, одна сессия; `exec_command` на каждую команду
отвечает её выводом без эха (проверено на плате 28.11). `show config` печатает `SSID`, `Channel`,
`IP Address` в формате, который уже разбирает `_parse_kv`. Сервер времени — `ntp
start|time|stop|drop|stat`, `stat` — одна строка JSON с `running`, `requests`, `replies`,
`dropped`, `last_epoch`.

## Goals / Non-Goals

**Goals:**

- Стенд на одной прищепке; тесты меняются только там, где меняется смысл (D7, блок N без роутера).
- Отказ оснастки — одна строка о причине и остановка прогона, а не сотня одинаковых ошибок.

**Non-Goals:**

- Дамп трафика (`capture`, порт 19000) и `SerialTransport` роутера не трогаем: на 2.5.0 не
  проверялись, стенд ими в обычном прогоне не пользуется.
- Работа стенда с METF как запасной оснасткой — путь METF удаляется целиком.

## Decisions

### 1. `programmer.py`: свой маленький клиент на pyserial

Класс `Programmer(port)`: `cmd(line) -> str` (одна строка ответа), `info()`, `board()`,
`log_begin()`, `log_read() -> (bytes, lost)`, `wave(lines) -> int` (мс), `wave_stat() -> dict`,
`hold(line)`, `release(line)`, `lines_off()`. Порт открывается с `rts=False, dtr=False` до
`open()` — так держит его и страница: DTR=0 при RTS=1 перезагружает C6. Если `#info` молчит
(программатор остался в мосте к ESP после прошивки), стенд один раз меняет DTR при RTS=0 — это
штатный выход из моста — и спрашивает снова.

Повторов нет. USB не теряет посылок, поэтому таймаут ответа или `SerialException` значат, что
программатор пропал или завис; это `ProgrammerGone`, и `conftest` останавливает прогон, как
раньше `MetfGone`. Альтернатива — переоткрывать порт — отвергнута: перезагрузка программатора
отпускает линии и очищает кольцо, и окно наблюдения всё равно негодно.

Замок на порт (`threading.Lock`) — дешёвая страховка: потоков, говорящих с платой, после D7 не
остаётся.

Поиск: записанный `[programmer] port`, иначе `serial.tools.list_ports` с VID 0x303a и ответом
`# waterius_flasher`. В файл найденный порт не пишется: имя `/dev/cu.usbmodem…` меняется от
гнезда, искать дешевле, чем чинить строку.

### 2. `dut.py`: линии по ролям

Номера выводов METF (`button_pin`, `ch0_pin`, …) уходят; линии называются как в программаторе:
`button`, `ch0`, `ch1`, `rst`. Строка пачки — `{'line': 'ch1', 'value': 0, 'at_ms': 0, 'edges':
[…]}`, клиент собирает из неё `#wave ch1 0 0 500,1500,…`. `_low` — пачка из одного участка с
ожиданием её длины, `wet` — `hold`/`release`. Потолки — программатора: 32 участка, 30 с
(`WAVE_MAX_PULSES` = 16). Индикатор METF (`rgb_*`) уходит.

`init()` (уборка после теста и подъём): `#release` по всем четырём линиям; на `линия занята` —
ждать и повторять до конца пачки (потолок — 30 с, длина самой длинной пачки). Не `#lines off`:
он закрывает приём лога, а `#esp log` после него очищает кольцо — строки сеанса, идущего во
время уборки, пропали бы молча.

### 3. `logwatch.py`: потери — флаг программатора

`poll()` читает `#log`, пока ответ полный (4096 байт), — за один опрос кольцо выбирается до дна.
Флаг потерь копится в счётчике `LogWatcher.lost_reads`; `loss_mark()`/`assert_no_loss()` сверяют
его прирост за окно. Разделения «вытеснено кольцом» и «переполнен приём UART» больше нет:
программатор отдаёт один флаг на обе беды, и текст отказа называет обе. Ветки про
`reboot_since`/`stall_since`, `serial_stat` клиента 0.3 и сетевые осечки удаляются: их нет.
`clear()` выбирает кольцо до дна и выбрасывает — вместо `serial_flush`.

Запас кольца: 64 КБ при пике потока около 13 КБ/с (222 строки/с по ~60 байт,
`05_air-and-loss.md`) — около 5 с, опрос раз в 0,5 с; у METF было 511 строк, около 2,3 с.

### 4. `router.py`: SSH через paramiko

`Transport` становится `run(line, timeout) -> str`; `SerialTransport` реализует его своими
`write_line`/`read_idle`, `TcpTransport` заменяется `SshTransport` (paramiko 5.x: curve25519,
ecdsa-nistp256, AES-GCM — проверено скриптом на плате). Одно соединение `SSHClient` на прогон,
на каждую команду — `exec_command`. Ошибка открытия канала (команда не ушла) — переподключение и
один повтор; обрыв после отправки — `RouterError`, как у прежнего TCP.

Ключ хоста: `[router] host_key` — отпечаток `SHA256:…`. Пусто — принять, записать через
`config._pin` и сказать в лог; не совпал — отказ подъёма с обоими отпечатками. Политика
paramiko — своя, сверяющая с этим полем, а не `AutoAddPolicy`.

`restart`: `exec_command('restart')` с коротким сроком, обрыв ожидаем; потом `reconnect()` с
потолком 60 с и проверка по аптайму — как сейчас. `version()` на 2.5.0 печатает несколько строк;
в лог идёт первая.

### 5. `clock.py`: `RouterClock` поверх консоли

Те же методы (`start`, `set_time`, `stop`, `drop`, `stat`, `requests_seen`), команды — `ntp …`
через `NatRouter.cmd`; ответ не `ok` — `RouterError` с текстом. `available()` — `ntp stat`
разбирается как JSON. Адрес для устройства — `ip_address` из `show config` (сейчас 192.168.4.1).
`Stand.clock` — `None` без роутера; фикстура блока N пропускает тесты, `requirements()` и
`ensure_clock` тогда `ntp_server` не трогают.

### 6. D7 — `over_session`

D7 становится как D7b/c: `stand.dut.series({1: (IMPULSE_WIDTH_MS, 0)}, count=10, step_ms=2000,
press_after=2)` — серия и нажатие одной пачкой (19 участков на `ch1` и один на `button`, 21,5 с
с паузой перед первым импульсом), затем два сеанса и сумма приростов против числа замыканий по
расписке. Поток и `DURING_*` уходят.

### 7. Конфигурация

`[metf]` уходит, `[programmer] port =` (пусто — искать), `[router] host_key =`. `StandConfig`:
`programmer_port`, `router_host_key`; поля выводов и `metf_host` удаляются. `towards` для своего
адреса — роутер или `ELSEWHERE`.

## Risks / Trade-offs

- [Роутер закрывает долгое SSH-соединение] → ошибка открытия канала даёт переподключение и
  повтор; keepalive paramiko раз в 30 с.
- [Пик лога длиннее 5 с без опроса — например, долгий `cmd` роутера] → флаг потерь делает окно
  негодным громко, а не молча.
- [`show config` другой сборки печатает иначе] → `ip_address` пуст — `ensure_clock` падает с
  текстом, а не прописывает пустой адрес.

## Migration Plan

1. В `stand.ini`: удалить `[metf]`, добавить `[programmer]`; `host_key` заполнится сам.
2. `pip install -r Utils/hil/requirements.txt` (paramiko).
3. Самотесты, затем полный прогон `pytest Utils/hil --stand`.

Отката к METF нет: роутер 2.5.0 пускает в консоль только по SSH, и прежний `router.py` с ним не
работает. Беда в новой оснастке чинится вперёд.
