Ватериус поддерживает отправку в
- сайт <a href="https://waterius.ru" target="_blank">waterius.ru</a>
- в Home Assistant по MQTT
- в WirenBoard по MQTT
- MQTT
- HTTP

Отправка в MQTT и HTTP происходит при каждом пробуждении устройства.

#### sc — выход на связь только при расходе

Режим для тех, кто поставил короткий период, чтобы видеть расход почти в
реальном времени, и не хочет платить за это батарейками.

Период пробуждения не меняется: Ватериус просыпается как обычно и опрашивает
счётчики, поэтому расход замечается ровно за заданный период. Экономится сеанс
связи — Wi-Fi поднимается, только если импульсы пошли. Если расхода нет трое
суток, устройство выходит на связь ради отметки, что оно живо.

Показания не теряются: импульсы считаются всё время, и накопленный за молчание
объём уезжает одной дельтой при следующей отправке.

`period_min` при этом остаётся периодом пробуждения — то есть минимальным
промежутком между выходами на связь. Максимальный промежуток задан константой
в прошивке и равен 4320 минутам (3 суток), настройке он не подлежит.

| Значение | Описание |
| --- | --- |
| 0 | Выключено: Ватериус выходит на связь каждое пробуждение (по умолчанию) |
| 1 | Включено: связь только при расходе, но не реже раза в 3 суток |

## Топики

Корневой топик задаётся в настройках, по умолчанию `waterius/<id>/`, где `<id>` — номер чипа
ЕСП. Завершающий слэш Ватериус отбрасывает, поэтому ниже `<корень>` — это, например,
`waterius/12380568`. Топик для discovery тоже из настроек, по умолчанию `homeassistant`.

### Что Ватериус публикует

| Топик | Когда | Что внутри |
| --- | --- | --- |
| `<корень>` | каждый сеанс, если включено «Автоматическое добавление в Home Assistant» | вся посылка одним JSON — поля перечислены выше |
| `<корень>/<поле>` | каждый сеанс, если discovery выключен | по одному топику на каждое поле посылки: `<корень>/ch0`, `<корень>/adc1`, `<корень>/alarm_wet0`, `<корень>/ar1` и так далее |
| `<топик discovery>/<тип>/waterius-<id>/<сущность>/config` | после настройки в портале, после короткого нажатия кнопки и в любом сеансе, где изменились версия прошивки, тип или ресурс входа, топики | конфигурация сущности для Home Assistant; пустое тело удаляет сущность, которая входу больше не нужна |
| `<корень>/<параметр>/set` с пустым телом | сразу после того, как принятая команда применена | стирает у брокера retained-команду: иначе она применялась бы в каждом следующем сеансе |

Флаг retain у посылки — «Retain Flag» в настройках MQTT, по умолчанию включён. Конфиги discovery
и пустые сообщения, стирающие команды, публикуются retained всегда, независимо от флага: Home
Assistant забирает конфиги у брокера при своём старте, а спящее устройство переслать их не может.

Топика доступности (LWT, `available`, `status`) у Ватериуса нет: устройство спит и почти всё
время офлайн.

### Что Ватериус принимает

Подписка — `<корень>/#`, и **только при включённом discovery**. Если «Автоматическое
добавление в Home Assistant» выключено, устройство не подписывается вовсе и команд не примет.

Команда — это топик `<корень>/<параметр>/set` с непустым телом. Ватериус спит, поэтому команда
применяется не мгновенно, а в ближайшем сеансе: публикуйте её **retained**, иначе брокер не
сохранит её до пробуждения. Применив команду, устройство стирает её (пустым retained-сообщением
в тот же топик) и отправляет посылку ещё раз, уже с новыми значениями.

Имена параметров — те же, что в портале; у части есть короткий синоним для Home Assistant,
и работают оба. Параметры с суффиксом входа `0` или `1` относятся к конкретному входу.

#### Получатели

Переключатели получателей принимаются всегда, а их адреса — только при включённом получателе:
сначала `mqtt_on`, потом `mqtt_host`.

| параметр | тип данных | что задаёт |
| --- | --- | --- |
| `waterius_on`, `http_on`, `mqtt_on` | 0, 1, true, false | включён ли получатель |
| `waterius_host`, `waterius_email` | строка | адрес и почта личного кабинета, если `waterius_on` |
| `http_url` | строка | адрес своего сервера, если `http_on` |
| `mqtt_host`, `mqtt_port`, `mqtt_login`, `mqtt_password`, `mqtt_topic` | строка / число | брокер, если `mqtt_on` |
| `mqtt_auto_discovery`, `mqtt_retain` | 0, 1, true, false | автообнаружение в Home Assistant и флаг retain |
| `mqtt_discovery_topic` | строка | топик discovery, если `mqtt_auto_discovery` |

Меняя `mqtt_topic`, `mqtt_auto_discovery` или брокер по MQTT, вы рубите сук под собой:
следующий сеанс пойдёт уже по новым настройкам, и прежние топики замолчат.

### Сущности Home Assistant

Автообнаружение создаёт 20 общих сущностей (показания времени и связи, период, режимы,
кнопка снятия тревог) плюс сущности на каждый вход. У входа со счётчиком их 13 — показания,
серийный номер, вес импульса, тип ресурса, четыре порога тревог и четыре индикатора тревог.
У входа с датчиком протечки только две: тип входа и `Alarm: water sensor` (класс `moisture`).
У выключенного входа — одна, тип входа. Список и русские названия —
[Home_Assistant_setup.md](Home_Assistant_setup.md).

Импульсы, дельта, уровень АЦП входа (`adc0`/`adc1`), серийный номер, вес импульса, тип ресурса
и тип входа едут атрибутами сенсора показаний, отдельных сущностей для них нет.
