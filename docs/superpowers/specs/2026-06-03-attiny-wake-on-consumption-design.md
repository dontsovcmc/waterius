# Пробуждение по потреблению воды (wake-on-consumption)

Дата: 2026-06-03
Статус: дизайн утверждён, готов к написанию плана реализации

## Проблема

Пользователи часто просят, чтобы устройство «просыпалось при потреблении воды» —
отправляло данные на сервер вскоре после того, как пошёл расход, а не только по
расписанию. При этом нужно:

1. сохранить периодический keep-alive (сервер должен видеть, что устройство на связи);
2. не будить ESP чаще, чем раз в N минут (главный расход батареи — это поднятие
   Wi-Fi на ESP, ресурс 3×AA рассчитан на 2–4 года).

## Модель поведения (утверждена с пользователем)

Вводим новый флаг настройки **«не просыпаться без потребления»** (`wake_on_consumption`).
Период `wakeup_period` (сущест3вующая настройка, задаётся пользователем, напр. 5 мин)
переосмысливается как «частота проверки потребления / минимальный интервал».
Keep-alive захардкожен — раз в сутки (1440 мин).

| Флаг | Поведение |
|------|-----------|
| **OFF** (по умолчанию) | Точно как сейчас: будим ESP каждые `wakeup_period`. Байт-в-байт текущая логика. |
| **ON** | На каждой границе `wakeup_period` будим ESP **только если** с прошлого пробуждения был ≥1 импульс. Если расхода не было — продолжаем спать. Принудительно будим, когда с прошлого пробуждения прошли сутки (keep-alive). Кнопка по-прежнему будит сразу. |

`wakeup_period` — это «пол»: чаще него по потреблению не просыпаемся. Потребление
никогда не *добавляет* пробуждений сверх ритма `wakeup_period`; оно лишь *подавляет*
пустые. В простое энергопотребление идентично текущему (watchdog тикает каждые 250 мс
так же, цикл просто не выходит наружу).

### Зафиксированные решения

- **Триггер** = любой импульс с прошлого пробуждения (не порог, не «активный расход сейчас»).
- **Минимальный интервал / частота проверки** = существующий `wakeup_period` (пользователь
  ставит, напр. 5 мин). Отдельной хардкод-константы «5 минут» нет.
- **Keep-alive** = захардкожен 1440 мин (сутки).
- **Хранение флага** — старший бит существующего байта `Config.model`. `model` уже
  лежит в `Config` (сохраняется/восстанавливается в EEPROM) и уже передаётся в Header,
  поэтому флаг бесплатно становится персистентным и транслируемым. Header **не растёт**
  (остаётся 24 байта), version-guard не нужен — старая прошивка пишет `model` со
  сброшенным старшим битом, что трактуется как флаг OFF. Переживает сброс Attiny
  (замена батареек).
- **Доп. предохранителей по батарее не нужно** — 5-минутного пола достаточно
  (худший случай при непрерывном расходе ≈12 пробуждений/час вместо 4/час).
- **Масштаб** — полный стек: Attiny + I2C + настройка на ESP + чекбокс в веб-портале +
  поле в JSON (MQTT/HA).

## Изменения в Attiny (`Attiny85/`)

### `Setup.h`

- Новая константа:
  ```c
  #define KEEPALIVE_PERIOD (1440L * ONE_MINUTE)   // суточный keep-alive, в тиках watchdog
  ```
- `struct Config` **не меняем** (размер прежний, Header остаётся 24 байта). Флаг
  кладём в старший бит существующего поля `Config.model`. Именованные маски:
  ```c
  #define MODEL_MASK               0x7F   // младшие биты — номер модели (0 или 2)
  #define FLAG_WAKE_ON_CONSUMPTION 0x80   // старший бит model — флаг режима
  ```
  `model` на Attiny не используется для ветвления (там работает compile-флаг
  `WATERIUS_MODEL`), так что переопределение старшего бита безопасно. Значение по
  умолчанию задаётся существующим литералом `.config = {0, 0, WATERIUS_MODEL, ...}` —
  старший бит сброшен ⇒ флаг OFF.

### `main.cpp`

- Поднять `FIRMWARE_VER` (платформенно через `platformio.ini`: текущее значение 38 → 39)
  — для трекинга версии; для совместимости парсера он не требуется (см. ниже).
- Новые глобальные:
  ```c
  volatile bool consumed_since_wake = false;   // был ли импульс с прошлого пробуждения
  ```
  (Сам флаг режима живёт в `info.config.model & FLAG_WAKE_ON_CONSUMPTION`, отдельная
  RAM-копия не нужна.)
- В `counting()` — там же, где импульс инкрементит счётчик, выставлять
  `consumed_since_wake = true;` для обоих входов (`value0++` и `value1++`).
- Новый хелпер — вся новая логика собрана здесь:
  ```c
  inline bool time_to_wake_up()
  {
      if (!(info.config.model & FLAG_WAKE_ON_CONSUMPTION))
          return wdt_count >= wakeup_period;            // поведение как сейчас

      if (wdt_count >= KEEPALIVE_PERIOD)
          return true;                                  // суточный keep-alive
      return (wdt_count >= wakeup_period) && consumed_since_wake;
  }
  ```
- В `loop()` заменить условие `while ((wdt_count < wakeup_period) && !button.pressed(event))`
  на `while (!time_to_wake_up() && !button.pressed(event))` и добавить сброс
  `consumed_since_wake = false;` сразу после `wdt_count = 0;`.

Поведение хелпера (period=5 мин, флаг ON):
- расход на 3-й минуте → проснётся на 5-й (соблюдён пол, расход доедет);
- расход на 7-й минуте → на 5-й не проснулся, на 7-й проснётся почти сразу (пол пройден);
- расхода нет совсем → проснётся через сутки (keep-alive).

### `SlaveI2C.cpp` / `SlaveI2C.h`

Новая команда `'W'` — приём флага от ESP, по образцу `getWakeUpPeriod()`:
```c
case 'W':            // ESP присылает флаг "не просыпаться без потребления"
    getWakeOnConsumption();
    break;
```
```c
void SlaveI2C::getWakeOnConsumption()
{
    uint8_t data = Wire.read();
    uint8_t crc  = Wire.read();
    if (crc == crc_8(&data, 1))
    {
        if (data)
            info.config.model |= FLAG_WAKE_ON_CONSUMPTION;
        else
            info.config.model &= ~FLAG_WAKE_ON_CONSUMPTION;
        saveConfig();    // персистентно в EEPROM, как делает getCounterTypes()
    }
}
```
При старте `setup()` флаг восстанавливается автоматически вместе со всем `info.config`
через существующий `config.get(info.config)`.

## Изменения в ESP (`ESP8266/`)

### `setup.h`
Новое поле в `Settings` по образцу `dhcp_off`:
```c
uint8_t wake_on_consumption = (uint8_t) false;
```
(Проверить, что статический ассерт размера `Settings` (960 байт) не падает; при
необходимости занять из резерва.)

### `master_i2c.cpp` / `master_i2c.h`
Новый метод по образцу `setWakeUpPeriod()`:
```c
bool MasterI2C::setWakeOnConsumption(bool on)
{
    BusyGuard guard(i2c_busy);
    uint8_t txBuf[3];
    txBuf[0] = 'W';
    txBuf[1] = on ? 1 : 0;
    txBuf[2] = crc_8(&txBuf[1], 1, INIT_ATTINY_CRC);
    return sendData(txBuf, 3);
}
```
Вызывать в `main.cpp` сразу после `setWakeUpPeriod(sett.period_min_tuned)`
(около строки 162), чтобы настройка обновлялась каждый цикл.

### Парсер Header — раскладка байта `model`
Header **не меняет размер** (24 байта), порядок и количество читаемых полей те же,
CRC прежний, version-guard не нужен. В `getData()` после чтения байта `model`
разложить его на номер модели и флаг:
```c
good &= getByte(data.model, crc);                  // читаем сырой байт как сейчас
data.wake_on_consumption = (data.model & 0x80) ? 1 : 0;
data.model &= 0x7F;                                 // дальше data.model — чистый номер
```
Так весь нижележащий код (`MODEL_NAMES[data.model]` в discovery, `json.cpp`, логи)
продолжает работать с чистым `model` без изменений. Совместимость автоматическая:
старый Attiny (ver 38) шлёт `model` со сброшенным старшим битом ⇒
`wake_on_consumption = 0` (OFF), модель корректна. В структуру данных Header на ESP
добавить поле `wake_on_consumption`.

### Веб-портал — `active_point_api.cpp` + `data/`
- Новый `PARAM_WAKE_ON_CONSUMPTION`, обработка через `save_bool_param(...)` в
  `applyCheckBoxParameter()` (как `PARAM_DHCP_OFF`).
- Чекбокс на странице настроек рядом с периодом пробуждения (HTML в `data/`),
  с пояснением: «Будить только при расходе воды; иначе раз в сутки».

### `json.cpp`
Добавить `wake_on_consumption` в `get_json_data()`, чтобы значение было видно в
HTTP/MQTT и настраивалось удалённо через Home Assistant (как другие настройки).

## Граничные случаи

- **Кнопка** (ручная передача / настройка) — работает как раньше, будит немедленно,
  независимо от флага.
- **Жёсткий сброс Attiny** (замена батареек): флаг восстановится из EEPROM в `setup()`
  вместе с `info.config` (бит в `model`).
  `wakeup_period`, как и сейчас, при сбросе берёт значение по умолчанию (15 мин) и
  корректируется ESP в первом же цикле — поведение не регрессирует.
- **Простой** (нет расхода): энергопотребление идентично текущему; цикл просто не
  выходит наружу до суточного keep-alive.

## Влияние на индикатор «на связи» (вне кода)

При флаге ON и полностью «сухих» сутках устройство отчитается раз в 24 часа. Любой
реальный расход — в пределах `wakeup_period`. Эвристика «онлайн» на сервере должна
допускать паузу до суток. Изменений прошивки не требует; задокументировать в описании
функции для пользователей.

## Проверка

- Сборка Attiny влезает в 8 КБ flash (`pio run -d Attiny85` — проверить прирост размера;
  логика добавляется минимальная).
- Сборка ESP проходит, статический ассерт размера `Settings` не падает
  (`pio run -d ESP8266`).
- Юнит-тесты ESP не затронуты (`pio test -d ESP8266 -e native`).
- Ручная проверка:
  - флаг OFF — поведение идентично текущему (будит каждые `wakeup_period`);
  - флаг ON, есть расход — раннее пробуждение не чаще `wakeup_period`;
  - флаг ON, нет расхода — пробуждение через сутки;
  - старый Attiny (ver 38) + новый ESP — данные читаются корректно, флаг = OFF
    (старший бит `model` сброшен; Header не менялся).

## Вне области задачи

- Изменение серверной эвристики «онлайн».
- Persistence самого `wakeup_period` на Attiny (остаётся RAM, как сейчас).
- Порог в импульсах/литрах и режим «активный расход сейчас» (осознанно не берём —
  выбран простой триггер «любой импульс»).
