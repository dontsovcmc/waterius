# Выпуск релиза прошивки

Команда «выложи релиз» — альфа из `dev`. Стабильный из `master` — только по
явному «выложи стабильный релиз».

## 1. Версии и тег
- ЕСП — `firmware_version` в `ESP8266/platformio.ini`, attiny — в `Attiny85/platformio.ini`.
- Тег альфы `<ЕСП>-<attiny>-alpha` (`2.0.53-47-alpha`), стабильного `v<ЕСП>-<attiny>`.
- Предыдущий релиз — `gh release list -R dontsovcmc/waterius`. Если версия ЕСП
  или attiny совпадает с предыдущим релизом, а изменения в ней есть — стоп,
  спросить: версию не подняли.
- Такого тега ещё нет: `git ls-remote --tags origin <тег>` пуст.

## 2. Сборка с нуля
Из свежего `origin/dev`, в task-workdir (`task_release_<тег>`), коммит записать.
- `secrets.ini` без `WIFI_SSID`: имена файлов без `-test`. Есть `-test` — стоп.
- ЕСП, для `waterius_2` и `esp01_1m`: `pio run -t clean`, `pio run`, `pio run -t buildfs`.
- attiny: `pio run -d Attiny85 -e waterius_2` и `-e attiny85`.
- Файлов ровно 8:
  `waterius_2-<v>.bin`, `waterius_2-<v>-fs.bin`, `waterius_2-<v>-full.bin`, `waterius_2-<a>.hex`,
  `esp01_1m-<v>.bin`, `esp01_1m-<v>-fs.bin`, `esp01_1m-<v>-full.bin`, `attiny85-<a>.hex`.

## 3. Проверка
- `ESP8266/scripts/run_tests.sh`, `Attiny85/scripts/run_tests.sh`,
  `node ESP8266/scripts/test_strings.js`, `node simulator/test_simulator.js`,
  `node simulator/test_worker.js`. Число тестов каждого набора записать для текста.

## 4. Текст
Источники: шапки `ESP8266/src/setup.h` и `Attiny85/src/main.cpp` за версии
после предыдущего релиза; влитые PR — `git log --merges <пред.тег>..<коммит>`.
Писать, что увидит пользователь, а не что поменялось в коде. Номера issue — `(#N)`.

Заголовок: `Альфа <ЕСП>-<attiny>: <2–3 главных изменения через запятую>`.

Разделы по порядку, образец — релиз `2.0.53-47-alpha`:
1. Абзац «**Альфа-версия.** Собрана из ветки `dev`…» дословно как в образце.
2. «Версии: **ЕСП x**, **attiny y**. Предыдущая альфа — [тег](ссылка) от <дата> (ЕСП …, attiny …).»
3. `## Что в этой версии главное` — 3–5 пунктов, начало жирным.
4. `## Прошивка ЕСП: <пред.> → <нов.>` — подразделы `###` по темам.
5. `## Прошивка attiny: <пред.> → <нов.>` — по абзацу на версию: **47.** …
6. `## Совместимость` — «ставятся парой», таблица «возможность → минимальные
   версии» (дополнить строками этого релиза), абзац про EEPROM attiny.
7. `## Файлы` — блок с адресами, адреса брать из `docs/flashing.md`;
   абзацы про `-fs.bin` и `-full.bin` со ссылкой на waterius.github.io/update.
8. `## Команды прошивки` — только команды avrdude и esptool, по разделу на плату
   (`### Ватериус-2`, `### Классик`). После каждого — «Логи при успешной прошивке:»
   с числами этой сборки: байты attiny из вывода pio, размеры `.bin` из файлов.
   Без подготовки, определения платы и пояснений.
9. `## Проверка` — коммит, число тестов по наборам.

## 5. Публикация
- Сначала черновик: `gh release create <тег> -R dontsovcmc/waterius --draft
  --target <полный sha> --title … --notes-file … <8 файлов>`.
- Ссылку на черновик отдать пользователю и ждать подтверждения. Без него не публиковать.
- После подтверждения: `gh release edit <тег> -R dontsovcmc/waterius --draft=false --latest`.
- Сверить: тег указывает на нужный коммит, файлов 8, размеры совпадают с локальными.
- Ссылка на альфу в `README.md` (строка «Альфа-версия…») ведёт на этот тег;
  если нет — PR в `dev` с правкой ссылки.
- Сервер обновлений по воздуху (`ESP8266/scripts/build_and_deploy.sh`) в релиз не входит.
- Отдать ссылку на релиз.
