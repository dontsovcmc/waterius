# Мультиязычный портал

Проект, а не описание готового: кода под этот документ ещё нет. Здесь — что
решено, почему именно так и в каком порядке делать.

## Цель

- **Waterius-2** — шесть языков в одной прошивке. Язык выбирается на странице
  настроек портала и хранится в настройках устройства.
- **Классика** — один язык, выбранный при сборке. Выбора в портале нет.
- Текст страниц виден **без JavaScript**. Окно captive portal на айфоне скрипты
  не выполняет (комментарий над обработчиками проверочных адресов в
  `ESP8266/src/portal/active_point.cpp:start_active_point`), и сейчас там,
  например, не видна причина ошибки подключения — её пишет скрипт.

## Как сейчас

Текст разложен по двум местам:

- **HTML** — `ESP8266/data/*.html`: 20 файлов, 70 902 байта, 282 фразы по-русски
  прямо в разметке;
- **`ESP8266/data/static/strings.js`** — сообщения по номерам (`tr()`,
  `fill_tr_id`). Прошивка отдаёт номер, текст подставляет скрипт: так работают
  `%wifi_connect_status%` и плашки `ESP8266/src/portal/active_point_api.cpp:get_api_main_status`.

Всего около 14 тысяч символов: ~25 КБ на язык кириллицей (UTF-8, два байта на
букву) и ~14–17 КБ латиницей.

## Место

| | Waterius-2 | Классика |
|---|---|---|
| Разметка флеша | `eagle.flash.4m1m.ld` | `eagle.flash.1m256.ld` |
| Прошивка сейчас / предел | 664 / 1019 КБ | 649 / 743 КБ |
| Файловая система | 1000 КБ, 125 блоков по 8 КБ, занято ~48 | 256 КБ, 64 блока по 4 КБ, занято ~59 |
| OTA | есть, `ESP8266/src/main.cpp:perform_ota_update` | нет |

Размеры прошивки — собранные `.bin` версии 2.0.51. Занятость ФС — расчёт по
размерам файлов с округлением до блока (как считать — [setup-portal.md](setup-portal.md),
«Место в файловой системе»); точную цифру даёт `pio run -t buildfs`.

## Почему не HTML на каждый язык

Самый простой вариант — готовые страницы `data/ru/…`, `data/en/…`, собранные
скриптом из одного шаблона. Он не помещается:

- **Waterius-2:** шесть наборов страниц — около 181 блока из 125. Сжатие не
  спасает: файл занимает минимум один блок, 6 × 20 страниц — уже ~120 блоков.
- Увеличить раздел ФС (`eagle.flash.4m2m.ld`) на устройствах, которые уже в
  поле и обновляются только по OTA, — значит сдвинуть файловую систему под
  живыми данными. Не делаем.

Поэтому текст уходит из файловой системы в прошивку.

## Решение

**Разметка одна на все языки, фразы в ней — ключи, строки — в прошивке. Набор
языков — флаг сборки:** `waterius_2` собирается со всеми шестью, `esp01_1m` — с
одним (по умолчанию русский).

```html
<h2>%T_SETUP%</h2>
<a class="btn" href="/wifi_settings.html?wizard=true">%T_WIFI_SETTINGS%</a>
```

1. **Файл переводов** — один на проект, в репозитории, но не в `ESP8266/data/`
   (всё оттуда уезжает в образ ФС). Строка: ключ, `ru`, `en`, … .
2. **Генератор** (pre-build скрипт PlatformIO) делает из него заголовок в
   `ESP8266/src/core/`: перечисление ключей и таблицу `PROGMEM
   [число языков][число ключей]` только для языков из флага сборки. Нет перевода
   — берётся русский. Генератор падает, если у ключа нет русского текста или
   ключ длиннее 32 символов (предел имени плейсхолдера, `TEMPLATE_PARAM_NAME_LENGTH`
   в `WebResponseImpl.h` библиотеки).
3. **Язык в настройках** (только Waterius-2) — один байт из
   `ESP8266/src/core/types.h:reserved9`. Размер `Settings` (960, под
   `static_assert`) не меняется, у уже прошитых устройств там 0 — русский.
4. **Подстановка** — в `ESP8266/src/portal/active_point.cpp:processor_main`,
   до существующей цепочки сравнений: префикс `T_`, затем двоичный поиск по
   отсортированной таблице ключей (~9 сравнений на фразу вместо прохода по
   63 `if`). Плюс `<html lang="%LANG%">`.
5. **Сообщения, которые сейчас идут номером** — причина ошибки Wi-Fi, плашки
   главной страницы, ошибки полей — прошивка отдаёт готовым текстом на языке
   устройства. Из `strings.js` уходят все фразы, остаётся логика: единицы
   измерения, арифметика импульсов.
6. **Выбор языка** — список на странице настроек Waterius-2, сохранение через
   `/api/save`.

### Цена по памяти

- **Waterius-2, шесть языков:** +100–130 КБ, прошивка ~800 из 1019 КБ. Каждое
  OTA-обновление прошивки тяжелее на те же килобайты; места под OTA (~2 МБ
  между прошивкой и ФС) хватает с запасом.
- **Классика, один язык:** ~25 КБ русского текста переезжают из HTML в прошивку,
  выходит ~675 из 743 КБ. Файловая система освобождается на столько же.

### Скорость и память при отдаче страницы

По коду форка `waterius/ESPAsyncWebServer#20230926` (`AsyncAbstractResponse::_ack`
и `_fillBufferAndProcessTemplates` в `WebResponses.cpp`):

- Страница не собирается в памяти целиком. Она уходит потоком: на каждом шаге
  выделяется кусок размером со свободное окно TCP (`client()->space()`),
  заполняется, отправляется и освобождается. Вариант lwIP в
  `ESP8266/platformio.ini` не задан, действует вариант PlatformIO по умолчанию,
  где `TCP_SND_BUF = 2 × TCP_MSS` — около 1 КБ на шаг.
- На каждую фразу — одна `String` с её текстом; самая длинная (подсказка к
  ошибке Wi-Fi) ~0,7 КБ.
- Текст длиннее ключа, и то, что не влезло в текущий кусок, ждёт следующего
  шага во внутреннем буфере `_cache` — порядка одного куска.
- Итого пик ~2–3 КБ на запрос. Он не зависит ни от размера страницы, ни от
  числа языков: таблицы лежат во флеше. Так уже сейчас отдаются все страницы с
  подстановкой.
- Скорость ограничивает сеть: ~1 КБ, затем ожидание подтверждения от клиента.
  По воздуху уходит столько же байт, сколько сейчас, — ключ превращается в тот
  же текст.
- Страницы, которые сейчас отдаются без подстановки (`captive_portal*.html` и
  другие), потеряют `Content-Length` и пойдут кусками (`chunked`). Браузеры и
  AT-плата стенда это поддерживают.

Цифры в миллисекундах — только замером на стенде: время обхода страниц (P1) до
и после, минимум свободной кучи и фрагментация. Куча и фрагментация уже есть в
каждой строке лога прошивки (`ESP8266/src/Logging.h`).

### Риски

- **Буквальный `%` в разметке** (CSS `width: 100%` и т.п.). Подстановка
  теперь идёт на всех страницах, и такой `%` надо писать как `%%`.
- **`%` в тексте перевода.** Подставленное значение с `%` ломает шаблонизатор
  ([ESPAsyncWebServer #1249](https://github.com/me-no-dev/ESPAsyncWebServer/issues/1249)),
  поэтому переводы идут через `ESP8266/src/portal/active_point.cpp:replace_value`,
  как все значения. Сообщения тревог с аргументом (`%s` в `strings.js`)
  форматируются в прошивке до подстановки.
- **Симулятор** (`simulator/`) повторяет подстановку плейсхолдеров — его
  генератор `simulator/gen_from_firmware.js` должен читать тот же файл переводов,
  иначе симулятор покажет ключи вместо текста.

## Порядок работ

1. **Генератор и только русский** на обеих моделях. Страницы переходят на
   ключи, а отдаваемый HTML побайтно равен нынешнему — это и проверка
   генератора, и гарантия, что поведение не изменилось.
2. **Байт языка, выбор в портале, английский** на Waterius-2.
3. **Остальные четыре языка.**

## Проверка

- Размеры: `pio run -d ESP8266 -e waterius_2` и `-e esp01_1m` против пределов из
  таблицы, `-t buildfs` для файловой системы (CI уже собирает образ ФС).
- Хост: `ESP8266/scripts/run_tests.sh` — у каждого ключа есть русский текст,
  ключи не длиннее 32 символов, Waterius-2 собран с шестью языками, Классика — с
  одним; `node ESP8266/scripts/test_strings.js`; `node simulator/test_simulator.js`.
- Стенд: `Utils/hil/test_portal.py` — ни одного неподставленного `%…%` на каждом
  языке; `Utils/hil/test_captive.py` — окно captive portal получает страницы с
  текстом.

## Как делают другие

- [Tasmota](https://github.com/arendst/Tasmota/blob/development/tasmota/language/en_GB.h) —
  язык выбирается при сборке (`tasmota/language/xx_XX.h`), один язык на
  бинарник; непереведённое показывается по-английски.
- [EMS-ESP32](https://docs.emsesp.org/Adding-Languages/) — одна прошивка, язык в
  настройках; строки прошивки в `local_translations.h`, веб-интерфейс переводится
  отдельно в JS. Начинали со сборок на язык, потому что «памяти на все переводы
  не хватает» ([issue #22](https://github.com/emsesp/EMS-ESP32/issues/22)); это
  ESP32.
- Строки во флеше на ESP8266 — только через `PROGMEM`, иначе они занимают
  оперативную память ([документация ядра](https://arduino-esp8266.readthedocs.io/en/latest/PROGMEM.html)).
  У ESPHome для таблиц строк есть `PROGMEM_STRING_TABLE`
  ([PR #13659](https://github.com/esphome/esphome/pull/13659)).
- Предел имени плейсхолдера в 32 символа —
  [ESPAsyncWebServer PR #176](https://github.com/me-no-dev/ESPAsyncWebServer/pull/176).
