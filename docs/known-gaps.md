# Расхождения между кодом и ожиданиями

Места, где поведение не соответствует тому, что подсказывает интерфейс или имя функции.
Найдены при разборе кода для этой документации, не проверялись на живом устройстве.

Это не список задач — часть из них может быть осознанной. Но каждое стоит проверить, прежде
чем строить на нём выводы.

## Чекбокс «Retain Flag» не сохраняется

`data/setup_send.html` содержит чекбокс `mqtt_retain`, а `active_point.cpp:processor_main`
подставляет в него текущее значение. Обработчика с именем `PARAM_MQTT_RETAIN` в
`applyCheckBoxParameter` и `applyNonCheckBoxParameter` нет.

Значит галочка отображается корректно, но снять её через портал нельзя: значение из формы
никуда не записывается. Работает то, что стоит по умолчанию (`mqtt_retain = true`,
`ESP8266/src/config.cpp:init_config`).

Проверить: `grep -c PARAM_MQTT_RETAIN ESP8266/src/portal/active_point_api.cpp` → 0.

## `mqtt_connect` возвращает успех после всех неудач

`ESP8266/src/ha/subscribe.cpp:mqtt_connect` перебирает попытки в цикле `do…while(--attempts)` и
после его исчерпания выполняет `return true`.

Практический ущерб ограничен: `send_mqtt` перед публикацией отдельно проверяет
`mqtt_client.connected()`. Но возвращаемое значение вводит в заблуждение, и подписка после
ложного успеха выполняется впустую.

## Скрытое поле `wifi_channel` игнорируется

`data/wifi_password.html` шлёт скрытое поле `wifi_channel`, обработчика с таким именем нет.

Логика при этом работает — но по другой причине: при сохранении нового SSID или пароля
`applyNonCheckBoxParameter` сам обнуляет кэш канала и BSSID, и признак «канал сменился» в
`post_api_save_connect` срабатывает из-за этого обнуления.

## Страница логов показывает статический файл

`/waterius_logs.txt` отдаётся из LittleFS, но в `ESP8266/src/` нет ни одного места, которое бы
этот файл писало. То есть страница логов показывает содержимое `data/waterius_logs.txt` из
образа файловой системы — заглушку, одинаковую на всех устройствах.

Ссылка на страницу с главной закомментирована в `data/index.html`, так что вживую её обычно не
видно.

Настоящие логи идут в UART и доступны только при сборке с `LOG_LEVEL_INFO` или
`LOG_LEVEL_DEBUG`.

## Канал сети в списке — не тот, что кажется

`get_api_networks` кладёт в каждый элемент списка `WiFi.channel()` — канал **текущего**
соединения станции, а не канал найденной сети. Для выбора сети из списка это значение
бессмысленно.

## Часть сущностей Home Assistant закомментирована

В `ESP8266/src/ha/resources.h` объявлены, но не публикуются `ENTITY_VOLTAGE_LOW`,
`ENTITY_BATTERY` и `ENTITY_PERIOD_MIN_TUNED`. Поля при этом уходят в payload, то есть данные
есть, а сущностей в HA нет.

Заряд батареи (`battery`) в payload помечен в [Export.md](../Export.md) как «фейковый» — он
считается из просадки напряжения, а не из реального заряда.
