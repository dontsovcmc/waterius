# Проверка HTTPS

Отправка показаний и обе загрузки OTA используют
`ESP8266/src/tls_client.cpp:configure_tls_client`. BearSSL проверяет имя сервера из URL,
даты сертификатов и доверие к ключу. `setInsecure()` и автоматического обхода ошибок нет.
Перенаправления отключены. Явно настроенный `http://` для показаний и MQTT не меняются;
OTA принимает только HTTPS.

## Доверенные сертификаты

`ESP8266/src/tls_certificates.h` содержит четыре сертификата в PROGMEM, без нового файла
LittleFS: раздел Classic почти заполнен. `X509List` живёт до закрытия сокета и освобождается
после него. В RAM разбираются только эти четыре сертификата, не весь список Mozilla.

### Облако Waterius

На 2026-11-02 `cloud.waterius.ru:443` предъявляет сертификат собственного издателя
`CN=waterius.ru, O=Waterius LLC`, без публично доверенной цепочки. Поэтому одного ISRG
недостаточно. Встроен сертификат сервера как **non-CA trust anchor**: BearSSL требует
совпадения subject и открытого ключа, проверяет имя сервера и даты. Этот сертификат
не получает права подписывать сертификаты других серверов.

- Subject: `CN=cloud.waterius.ru, C=RU, ST=Moscow, L=Moscow, O=Waterius LLC, OU=Waterius Community`.
- Действует: 2019-03-22 — 2041-02-14.
- SHA-256 DER: `4CA3894D5A6ED19CFF4240FF242089721097DB9485F144DE821AB664D16C1D9C`.

**Перед вливанием сопровождающий должен сверить этот отпечаток со своим сертификатом.**
Сертификат получен из текущего TLS-handshake, его подлинность по независимому доверенному
каналу автором правки не подтверждена. Проверка в приборе использует только встроенный
якорь: не загружает доверие с сервера и не запоминает первый предъявленный ключ.

При смене ключа частного сертификата новый доверенный сертификат нужно включить в прошивку
заранее. Можно держать старый и новый одновременно. Переход облака на сертификат с полной
цепочкой до встроенного публичного корня не требует нового пина.

Самоподписанные корни с [официальной страницы Let's Encrypt](https://letsencrypt.org/certificates/):

| ISRG Root X2 | https://letsencrypt.org/certs/isrg-root-x2.pem | `69729B8E15A86EFC177A57AFB7171DFC64ADD28C2FCA8CF1507E34453CCB1470` |

Также включён TLS-корень Минцифры **Russian Trusted Root CA** (RSA 4096, SHA-256,
2022-03-01 — 2032-02-27). Источник — [страница Госуслуг](https://www.gosuslugi.ru/crt),
PEM загружен по HTTPS с официального CDN:
https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt.
SHA-256 DER: `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`.

Промежуточные сертификаты, включая Russian Trusted Sub CA 2024, должен присылать сервер;
они не объявляются самостоятельными корнями доверия. В тестах есть настоящая цепочка
`www.sberbank.ru`, заранее проверенная этим корнем. ГОСТ-сертификаты электронной подписи
ГУЦ не входят в этот набор: это другой PKI, а криптобиблиотека ESP8266 не реализует ГОСТ.

Они позволяют менять обычные серверные сертификаты без обновления прибора, пока цепочка
ведёт к одному из этих корней. Сервер должен отдавать промежуточные сертификаты: BearSSL
не скачивает их по AIA. Для собственного сервера с другим CA нужно добавить его доверенный
корень в этот заголовок, обновить `TLS_CERTIFICATE_COUNT` и пересобрать прошивку. Не следует
возвращать `setInsecure()` ради совместимости.

## Время

`ESP8266/src/sync_time.cpp:get_tls_time` возвращает ноль, пока у часов нет опоры:
успешного NTP или оценки по сохранённой NTP-синхронизации. Начальная дата
`START_VALID_TIME`, даже если она уже продвинулась на несколько секунд, опорой не считается.
`last_send` тоже недостаточно: оно могло сохраниться после неудачной первой синхронизации.

Если NTP не отвечает при первом запуске, HTTPS и OTA отклоняются. После успешной
синхронизации допустим существующий механизм оценки времени и сохранённого последнего
времени при сбое NTP. Без точных часов нельзя гарантировать точность проверки дат на
границе срока действия сертификата. NTP остаётся неаутентифицированным.

## Проверка на устройстве

До стенда сертификаты проверяются без сети настоящим X.509-движком BearSSL:

```bash
sudo apt-get install g++ libbearssl-dev openssl
python3 ESP8266/scripts/test_tls.py
```

Скрипт использует сертификаты из заголовка прошивки и фиксированные публичные цепочки
Let's Encrypt и Russian Trusted из `ESP8266/test/tls/`. Проверяет приём правильного
сертификата, отказ при чужом имени, неверных датах, подменённом ключе и испорченной подписи.
Приватный сертификат проверяется и как non-CA: он не становится издателем. Проверка входит
в CI. Это проверка X.509 на хосте; расход памяти, Wi-Fi и запись флеша требуют стенда.

После сборки обеих моделей и хостовых тестов проверить на стенде:

1. При успешном NTP отправка в настоящее облако проходит, `TLS: time is unknown` нет.
2. Сервер с чужим ключом при том же имени отклоняется до отправки HTTP-тела.
3. Сервер с доверенным CA, но неверным именем или истёкшим сертификатом отклоняется.
4. После сброса, при заблокированном NTP, HTTPS отклоняется и после нескольких секунд
   работы, и после повторного пробуждения. После восстановления NTP отправка проходит.
5. При недоступном NTP после прежней успешной синхронизации используется сохранённая опора.
6. OTA с правильной цепочкой проходит; HTTP URL, HTTP redirect и недоверенный сертификат
   отклоняются. Для проверки отказа использовать тестовые образы и стенд.

Проверка HTTPS не заменяет подпись образов: существующие команды OTA из MQTT и контроль MD5
остаются отдельной частью модели доверия.
