# Проверка HTTPS

При отправке показаний и скачивании обновлений прибор проверяет сертификат сервера:
кому он выдан, кем подписан и не истёк ли срок действия. Если проверка не прошла,
соединение отменяется.

Обновления скачиваются только по HTTPS. Отправку показаний на явно указанный адрес
`http://` по-прежнему можно настроить, но такое соединение не шифруется.

## Какие сертификаты включены

В `ESP8266/src/tls_certificates.h` хранятся:

- сертификат облака `cloud.waterius.ru`;
- корневые сертификаты Let's Encrypt — ISRG Root X1 и X2;
- корневой сертификат Минцифры — Russian Trusted Root CA.

Они записаны во флеш-память прошивки. Файловая система для этого не нужна — у Classic
в ней мало свободного места. При подключении эти четыре сертификата разбираются в RAM,
а после закрытия соединения память освобождается.

### Облако Waterius

На 2 ноября 2026 года облако использует сертификат, подписанный собственным центром
`waterius.ru`. Обычные публичные корневые сертификаты для него не подходят.

В прошивку добавлен сертификат самого сервера. Прибор сверяет имя владельца и открытый
ключ, а затем проверяет адрес сервера и срок действия. Этот сертификат не добавляется
как центр выдачи сертификатов для других сайтов.

Он действует с 22 марта 2019 года по 14 февраля 2041 года. Его отпечаток SHA-256:

```text
4CA3894D5A6ED19CFF4240FF242089721097DB9485F144DE821AB664D16C1D9C
```

Перед слиянием разработчикам нужно сверить этот отпечаток со своим сертификатом.
Сейчас он получен при подключении к облаку; отдельного подтверждения, что это именно
сертификат Waterius, пока нет.

Если ключ сервера меняется, новый сертификат нужно заранее добавить в прошивку.
На время перехода можно оставить оба. Если облако перейдёт на сертификат, выданный
одним из уже включённых публичных центров, менять прошивку не потребуется.

### Let's Encrypt и Минцифры

Корневые сертификаты взяты с [сайта Let's Encrypt](https://letsencrypt.org/certificates/)
и [Госуслуг](https://www.gosuslugi.ru/crt). Отпечатки рассчитаны по сертификатам в формате DER:

| Сертификат | Файл | SHA-256 |
|---|---|---|
| ISRG Root X1 | [PEM](https://letsencrypt.org/certs/isrgrootx1.pem) | `96BCEC06264976F37460779ACF28C5A7CFE8A3C0AAE11A8FFCEE05C0BDDF08C6` |
| ISRG Root X2 | [PEM](https://letsencrypt.org/certs/isrg-root-x2.pem) | `69729B8E15A86EFC177A57AFB7171DFC64ADD28C2FCA8CF1507E34453CCB1470` |
| Russian Trusted Root CA | [PEM](https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt) | `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31` |

Корень Минцифры использует RSA 4096 и SHA-256, действует с 1 марта 2022 года
по 27 февраля 2032 года. Он поддерживается библиотекой BearSSL на ESP8266.
Сертификаты электронной подписи по ГОСТ относятся к другой системе и здесь не поддерживаются.

Промежуточные сертификаты, в том числе Russian Trusted Sub CA 2024, должен присылать сервер.
Прибор сам их не скачивает. Пока сертификат сервера подтверждается одним из включённых
корней, его обычная замена не требует обновления прошивки.

Для собственного сервера с другим центром выдачи нужно добавить его корневой сертификат
в `tls_certificates.h`, изменить `TLS_CERTIFICATE_COUNT` и пересобрать прошивку.

## Зачем прибору время

Чтобы проверить срок действия сертификата, прибор должен знать текущую дату.
Он получает её от сервера времени NTP. Между запросами используется расчёт времени
по сохранённой успешной синхронизации.

Если при первом запуске получить время не удалось, HTTPS-подключение отменяется.
Начальная дата из прошивки для проверки сертификатов не подходит, даже если часы уже
отсчитали несколько секунд. Одного `last_send` тоже недостаточно: дата отправки могла
сохраниться после неудачного запроса времени.

После успешной синхронизации прибор может использовать сохранённое время при сбое NTP.
Ошибка часов влияет на проверку сертификатов вблизи начала или конца их срока действия.
Запросы NTP остаются без проверки подлинности источника.

## Проверка на компьютере

```bash
sudo apt-get install g++ libbearssl-dev openssl
python3 ESP8266/scripts/test_tls.py
```

Тесты проверяют сертификаты через BearSSL. Используются сертификаты из прошивки и
сохранённые цепочки Let's Encrypt и Минцифры из `ESP8266/test/tls/`. Интернет не нужен.

Всего 14 проверок: действующие сертификаты принимаются, а неверное имя сервера,
неподходящий срок действия, чужой ключ и повреждённая подпись приводят к отказу.
Также проверяется, что цепочка Минцифры не принимается без её корневого сертификата.

## Что проверить на приборе

1. Показания отправляются в облако после получения времени.
2. Поддельный сертификат, неверное имя сервера и истёкший срок приводят к отказу
   до отправки показаний.
3. После сброса при недоступном NTP отправка по HTTPS отменяется, в том числе при
   повторном пробуждении. После восстановления NTP показания отправляются.
4. Если раньше время уже удалось получить, отправка работает при временном сбое NTP.
5. Обновление по HTTPS проходит. HTTP-адрес, перенаправление или недоверенный сертификат
   отменяют загрузку. Для этой проверки нужны стенд и тестовые файлы прошивки.
6. Во время подключения хватает свободной памяти, а прибор успевает завершить отправку
   до отключения питания со стороны attiny.

Проверка соединения не добавляет подпись файлов прошивки. Команды обновления через MQTT
и проверка MD5 работают как раньше.

## Где находится код

- `ESP8266/src/tls_client.cpp:configure_tls_client` — настройка проверки сертификатов.
- `ESP8266/src/sync_time.cpp:get_tls_time` — время для проверки срока действия.
- `ESP8266/src/tls_certificates.h` — встроенные сертификаты.
